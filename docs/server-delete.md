# 서버 측 빠른 삭제

대규모 폴더 삭제는 파일마다 SFTP 요청을 보내는 대신 서버의 `find`와 `rm -rf`로 처리한다.

1. SFTP에서 실제 폴더인지 확인하고 임의 이름·내용의 마커를 만든다.
2. 같은 부모에 권한 0700인 `.limen-delete-<GUID>` 작업 폴더를 만들고, 선택 폴더를 그 안의 `payload`로 이동한다.
3. 이동한 폴더의 마커를 다시 검증한다. 원래 경로에 새 폴더가 생겨도 삭제 대상에 포함하지 않는다.
4. 현재 SFTP 연결에서 승인한 호스트 키와 정확히 일치하는 SSH 연결만 사용한다. 키 변경은 자동 승인하지 않는다.
5. 명령은 `/bin/sh -c '…'` 로 감싸 보낸다. 서버는 계정의 로그인 셸로 명령을 실행하는데, csh·tcsh·fish는 스크립트 문법을 해석하지 못하고 그 시점엔 폴더가 이미 작업 폴더로 옮겨진 뒤이기 때문이다. 셸은 작업 폴더·payload·마커의 심볼릭 링크 여부를 검사하고 `cd -P`로 대상 폴더에 진입한 뒤 마커 내용을 확인한다. 확인과 삭제는 한 명령 안에서 실행한다.
6. 마커를 제외한 내용을 현재 디렉터리 기준으로 일괄 삭제한다. 숨김 파일과 특수문자 이름을 지원하며 명령행 길이는 `find -exec … +`로 제한한다.
7. SFTP에서 마커를 다시 확인하고 마커와 빈 폴더를 제거한다. 셸 성공 코드만으로 삭제 완료를 보고하지 않는다.

## 실패 처리

- 준비 단계에서 마커 작성이나 작업 폴더 생성이 불가능하면 일반 SFTP 삭제를 사용한다. 빈 폴더 삭제 권한과 내부 파일 작성 권한은 다를 수 있다.
- 이동 이후 셸 접속이 시작되지 않았거나 사전 검사에서 삭제 전에 거부된 경우에는 **이동된 경로만** SFTP로 삭제한다.
- 이동 응답 유실, 실행 중 연결 끊김·시간 초과, 부분 삭제, 결과 검증 실패 시에는 재귀 삭제를 재시도하지 않는다. 오류창에 남은 작업 폴더 경로를 표시한다. 원래 이름으로 자동 복원하지도 않는다.
- 불확실한 실패 뒤에는 서버 프로세스가 종료되었는지와 작업 폴더 내용을 확인한 후 수동 처리해야 한다.

## 한계

이 방식은 배포 작업이 원래 경로를 교체하는 경우와 SFTP/셸 경로 불일치를 방어한다. 같은 계정 또는 root 권한으로 임시 폴더·마커를 의도적으로 변조하는 프로세스까지 격리하는 보안 경계는 아니다. 폴더의 다른 별칭을 통해 계속 내용을 쓰는 프로세스도 정지시키지 않는다. 변경이 계속되면 마지막 빈 폴더 제거가 실패할 수 있다.

원격 서버에서 POSIX 셸과 필요한 `find` 옵션을 지원해야 빠른 삭제를 사용할 수 있다. 실제 SSH 서버 및 chroot 환경의 통합 접속 검증은 별도 수행이 필요하다.

## 검증

`dotnet run --project src/Limen.UiTests/Limen.UiTests.csproj -- --regression-only`

회귀 테스트는 핀 일치·불일치, 위험 경로, 안전한 fallback 대상, 원래 경로 재생성, 이동 응답 유실, 대상 교체, 불확실한 셸 결과, 잘못된 성공 응답을 검사한다. Git Bash가 설치된 Windows에서는 실제 `find`/`rm` 명령으로 마커 불일치, 경로 불일치, 중첩 폴더·숨김·특수문자 이름 삭제도 검사한다. 네이티브 심볼릭 링크 생성 권한이 없으면 해당 실제 링크 테스트는 SKIP으로 표시한다.
